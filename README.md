# Anomaly Memory Compression

A controlled study of whether **compressing the normal-feature memory bank**
of training-free industrial anomaly detectors (PatchCore-style) affects
detection and localisation of **small defects** differently from large ones.
Comparisons are made at matched memory bytes on original MVTec AD.

**Status: Phase 0** (literature, protocol, infrastructure). No model results
exist yet. See [`docs/STATE.md`](docs/STATE.md).

## Layout

| Path | Contents |
|---|---|
| `src/anomaly_memory/` | Library. Every scientific module lives here (`data/`, `eval/`, `features/`, `memory/`, `baselines/`) plus the harness (`config`, `manifest`, `identity`, `budget`, `runctx`) |
| `tools/` | CLI entrypoints, each `--config <name>`: `acquire_data`, `profile_data`, `metric_selfcheck`, `evaluator_sanity`, `evaluate`, `extract_features`*, `run_baseline`*, plus `budget`, `colab_ctl`, `sync_results`, `build_notebook`, `precommit_check`. *Blocked until Phase 0 approval |
| `configs/` | One YAML per experiment, validated strictly and immutable once run. `configs/control/` holds the phase gates and accelerator allocations |
| `notebooks/runner.ipynb` | Thin Colab runner, generated by `tools/build_notebook.py`. `colab_driver.py` defines its subprocess wrappers |
| `tests/` | CPU tests that need no dataset. `tests/reference/mvtec_official/` holds MVTec's evaluation code (BSD-3), used only to verify our metrics |
| `docs/` | `STATE`, `REALITY_CHECK` (pre-registration), `CLAIMS`, `DECISIONS`, `COMPUTE_LEDGER`, `LITERATURE`, `DATA`, `COLAB` |
| `scripts/` | `make_figures.py` and `make_tables.py`, which read manifests only |
| `paper/` | `main.tex` on Elsevier `elsarticle`, `refs.bib`, `generated/` (macros/tables from manifests), `figures/` (generated PDFs) |
| `results/manifests/` | Mirror of complete run manifests plus small JSON results (`tools/sync_results.py`). Heavy artifacts stay on Google Drive |

## Quick start

Laptop (CPU only):

```bash
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -r requirements-dev.txt
git config core.hooksPath .githooks     # pre-commit guard: secrets, data, blobs, notebook outputs
.venv/bin/python -m pytest -q
cd paper && make PY=$PWD/../.venv/bin/python
```

Colab: follow [`docs/COLAB.md`](docs/COLAB.md). In short, open `notebooks/runner.ipynb` on a **CPU** runtime and run Cells 1 → 2 → 3.

## Data

MVTec AD (CC BY-NC-SA 4.0) is **not** redistributed. `tools/acquire_data.py` downloads it from the official page, verifies it, and persists the archive on your Google Drive. See [`docs/DATA.md`](docs/DATA.md).

## Reproducibility

Every run writes a manifest recording:

- config, dataset and split hashes;
- git SHA and dirty state;
- seed, environment (`pip freeze`) and hardware;
- metric values and artifact hashes;
- `complete: true`, written last.

Loading re-validates every manifest and refuses incomplete or incompatible runs. Every paper number and figure is regenerated from manifests by `scripts/`.

Bitwise cross-GPU reproduction is not promised. What is promised is statistical reproduction across ≥3 seeds.
